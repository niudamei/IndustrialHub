## 当前数据链路

目前已实现：

`CommunicationManager` → `MonitorPage / TrendPage`

以及本次补充的：

`CommunicationManager TX/RX` → `DataManager` → `SQLite communication_history` → `HistoryPage`

另已建立并接入业务解析链路：

`CommunicationManager RX` → `ProtocolManager` → `IProtocolParser` → `BusinessDataPoint` → `BusinessDataManager（最新值内存缓存）` → `DataManager` → `SQLite business_data_history`

模拟业务数据另有独立链路：`MonitorPage 模拟业务变量` → `BusinessDataPoint` → `BusinessDataManager` → `DataManager / AlarmManager`；它不伪装成 CAN/TCP 原始帧，也不经过真实协议解析器。

通信配置页可按设备显式绑定 JSON 示例解析器；默认不解析。业务变量最新值缓存保存在内存，且已异步批量写入独立 business_data_history 表；实时趋势页读取最新值，业务历史查询 API 已支持设备、变量、时间范围和分页。历史页已分为通信原始帧与业务变量历史两个页签，业务变量历史支持筛选、分页、当前页曲线和 CSV 导出。

## 当前边界与验收原则

- 模拟设备只用于演示和测试，不得影响真实设备。
- TX 统计代表本软件/驱动接受发送请求，不代表远端已收到。
- 未明确协议的设备只保存原始帧，不推断业务含义。
- GitHub 文件更新成功不代表用户本地 Qt 编译通过；每个阶段仍需本地构建和测试验收。

### TCP 自动重连（本阶段）

TCP 设备在连接意外中断或连接错误后自动重试，等待时间按 1、2、4、8、16、30 秒退避；连接恢复后重置退避计数。用户手动断开、释放设备或关闭全部通信时会停止自动重连。自动重连目前仅用于 TCP；UDP、RS485、CAN/CAN-FD 不会被错误地当作 TCP 会话处理。配置页通信日志会显示重连尝试次数与等待时间。
