# IndustrialHub

基于 Qt 6 Widgets + Qt Designer + CMake 的工业设备管理上位机项目。历史查询使用 Qt Concurrent 在线程池执行。

## 当前版本

- Qt：6.5 或更高版本
- C++：17
- 构建：CMake + Ninja
- UI：Qt Widgets / Qt Designer（`.ui`）
- 数据库：SQLite（Qt SQL）
- 网络：Qt Network
- 当前版本：0.9.0

## 已实现模块

### 设备管理与数据持久化

- `DeviceManager` 统一管理设备信息，支持新增、编辑、删除、查询和状态更新。
- 使用 QSQLITE，首次启动自动创建数据库目录和数据表。
- 程序启动时从数据库加载设备；增删改操作先写数据库，成功后更新内存。
- 设备编号忽略大小写，避免重复编号。
- 程序重启时将上次运行遗留的在线状态重置为离线。

### 通信接口与驱动

- `ICommunication` 抽象基类统一定义打开、关闭、状态、发送和接收接口。
- `SimulatedCommunication`：无硬件回环模拟。
- `TcpCommunication`：TCP 客户端，支持主机名、IPv4 和 `[IPv6]:端口`。
- `UdpCommunication`：UDP 数据报，支持 IPv4 和 `[IPv6]:端口` 数字地址。
- `Rs485Communication`：基于 Qt SerialPort 的串口收发，支持波特率、数据位、校验位、停止位和流控。
- `SlcanCommunication`：通过 Qt SerialPort 驱动 CANable 2.0 SLCAN，支持经典 CAN 与 CAN-FD。
- SLCAN 地址格式：经典 CAN 使用 `COM4,1000000`；CAN-FD 使用 `COM4,1000000,2000000`。串口波特率按当前适配器配置为 1 Mbps。
- CAN 仲裁段支持 10k、20k、50k、100k、125k、250k、500k、800k、1M；CAN-FD 数据段支持 2M 或 5M。
- CAN 经典帧支持标准/扩展 ID；CAN-FD 支持标准/扩展 ID、BRS 和 0-64 字节合法 DLC 长度映射。
- SLCAN 帧命令使用 `t/T`（经典 CAN）、`d/D`（CAN-FD 无 BRS）、`b/B`（CAN-FD 启用 BRS）。标准 ID 使用小写，扩展 ID 使用大写；发送时界面输入不需要手动添加回车符。
- 示例：经典扩展帧 `T18AABBCC3112233`；CAN-FD 标准帧（12 字节）`d7E09112233445566778899AABBCC`。
- Qt SerialPort 是可选模块：未安装时主程序仍可构建，但 RS485 和 SLCAN 驱动不会注册。

### 多设备通信管理与 UI

- `CommunicationManager` 按设备编号管理独立通信实例，支持多个设备同时工作、单设备断开、全部断开、数据发送和信号转发。
- 通信类型使用工厂注册；TCP、UDP、模拟通信默认可用，安装 Qt SerialPort 后自动注册 RS485、CAN 和 CANFD。
- 通信配置页面支持选择设备、连接/断开、发送 HEX 或 SLCAN 帧命令，并查看 TX/RX 和错误日志。
- 设备在线状态由统一健康监测器管理：通信连接后等待首帧 RX，收到实际 RX 后标记在线；连接静默超过超时阈值后自动离线，恢复 RX 后自动恢复在线。TX 不作为设备存活依据。

### 通信历史数据与统一数据入口

- `DataManager` 统一接收 `CommunicationManager` 发出的 TX/RX 事件。
- 通信记录采用批量事务写入 SQLite，保存毫秒时间戳、设备编号、方向、原始字节和字节数。
- 历史数据页面支持日期范围、设备编号、TX/RX 方向筛选，按 200 条分页查询。
- 支持导出当前页 CSV，也支持按当前时间/设备/方向筛选条件后台流式导出全部记录（UTF-8 BOM），导出过程逐行写盘，不把全量数据加载到内存。
- 当前保存的是通信原始帧，不会在缺少设备协议定义时臆测温度、电流、位置等业务字段。

### 统一业务数据模型与协议解析基础

- `BusinessDataPoint` 统一描述设备编号、变量编号、变量名称、数值、单位、时间戳、质量状态和来源协议。
- `IProtocolParser` 定义协议解析接口；具体设备协议通过独立解析器实现，不耦合通信驱动。
- `ProtocolManager` 支持注册解析器、按设备编号绑定解析器，并通过 Qt signal 发布解析结果。
- 新增 Modbus RTU/TCP 编解码基础：读保持寄存器（0x03）、读输入寄存器（0x04）、写单寄存器（0x06）、写多寄存器（0x10），包含 RTU CRC16、TCP MBAP 长度/事务 ID 校验、异常响应解析；当前为协议帧层，尚未接入串口/TCP 轮询 UI。
- 当前提供 `JsonProtocolParser` 作为通用 JSON 示例解析器，支持 ISO 8601 时间戳、多个业务变量和 Good/Uncertain/Bad 质量状态。
- JSON 示例解析器不会自动套用到 CAN、CAN-FD 或私有 RS485 报文。真实设备必须在拿到协议文档后单独实现和绑定解析器。
- 解析采用整帧校验：任意变量字段不合法时整帧失败，不输出半帧数据。

JSON 示例：

```json
{
  "timestamp": "2026-11-13T10:20:30.123Z",
  "values": [
    {"id": "temperature", "name": "温度", "value": 26.5, "unit": "°C", "quality": "good"},
    {"id": "rpm", "name": "转速", "value": 1200, "unit": "rpm", "quality": "uncertain"}
  ]
}
```

### 业务数据管理与通信链路接入

- 主窗口创建 `ProtocolManager` 和 `BusinessDataManager`，将通信 RX 信号交给协议管理器。
- 通信配置页可以为当前设备选择“不解析原始数据”或“JSON 示例协议”；默认是不解析。
- 当前协议绑定仅在本次程序运行期间有效；重新启动后默认恢复为不解析，避免未经确认的协议配置长期生效。
- 只有显式绑定 JSON 的设备，其 RX payload 才会进入 JSON 解析器。未绑定的 CAN/CAN-FD/RS485 等设备仍只保留原始通信帧。
- 解析成功后，业务数据管理器按设备编号和变量编号保存最新值；较旧时间戳的数据不会覆盖较新的值。
- 通信日志会显示解析后的变量名称、变量编号、数值、单位和质量状态。
- 当前业务数据最新值缓存仅保存在内存中，程序重启后会清空；业务变量历史入库仍待实现。

## 自动化测试

启用 CMake 的 `BUILD_TESTING` 时构建：

- `communication_smoke_test`：模拟通信回环。
- `tcp_communication_smoke_test`：TCP 本机回环。
- `udp_communication_smoke_test`：UDP 本机数据报回环。
- `communication_manager_smoke_test`：多设备管理、数据路由和资源释放。
- `rs485_communication_smoke_test`：Qt SerialPort 可用时，检查串口参数格式。
- `slcan_frame_codec_test`：SLCAN 经典 CAN/CAN-FD 帧编解码、DLC 映射和非法帧校验。
- `slcan_communication_smoke_test`：Qt SerialPort 可用时，检查适配器参数校验。
- `datamanager_history_test`：检查 TX/RX 事件入库、历史筛选、原始字节回读及复用总数的分页查询。
- `modbus_codec_test`：检查 Modbus RTU/TCP 请求帧、CRC、MBAP、寄存器响应、异常响应和非法参数。
- `device_database_test`：检查设备分组、启用状态和通信配置字段的 SQLite 持久化。
- `device_health_monitor_test`：检查每设备独立活动跟踪、首帧超时、在线超时、RX 恢复和手动断开。
- `json_protocol_parser_test`：检查 JSON 业务变量解析、质量状态、设备绑定、信号分发和非法报文拒绝。
- `business_data_manager_test`：检查业务变量最新值、大小写不敏感查询、旧时间戳保护和清理。

构建后运行：

```powershell
ctest --test-dir build --output-on-failure
```

TCP/UDP/模拟测试使用本机回环，不需要真实设备；串口配置测试也不要求连接硬件。

## Windows 构建

建议使用 VS Code + CMake Tools，选择 Qt 6 MinGW 64-bit 工具链。

```powershell
cmake -S . -B build -DCMAKE_PREFIX_PATH="D:/qt/6.10.3/mingw_64"
cmake --build build --config Debug
ctest --test-dir build --output-on-failure
```

请按本机 Qt 安装目录调整 `CMAKE_PREFIX_PATH`。如果没有安装 Qt SerialPort，CMake 会提示串口驱动被禁用，不影响 TCP/UDP 和主程序。

## 报警管理（当前阶段）

业务解析输出的 `BusinessDataPoint` 会并行进入 `AlarmManager`。报警规则支持设备/变量匹配、低限/高限、启用状态和 Info/Warning/Critical 等级；仅 `Good` 质量且为有限数值的数据参与阈值判断。报警事件支持 ACTIVE、ACKNOWLEDGED、RECOVERED、RECOVERED_ACK 状态，并持久化到与通信历史共用的 SQLite 文件。报警中心可查看事件并填写确认人。

报警中心提供新增阈值规则入口，规则与报警事件均持久化到 SQLite；当前已有新增和确认操作，规则编辑/删除/启停及报警筛选仍待完善。JSON 示例协议仍需用户显式绑定到设备，不能将未知 CAN/RS485 报文当作业务变量解析。


## 模拟业务变量与报警演示

在“实时监控 → 模拟设备（独立演示区）”启动模拟后，系统会为三台虚拟设备分别生成温度、转速和电流业务变量，并送入统一的 `BusinessDataManager` 与 `AlarmManager`。勾选“温度超限演示（触发报警）”后，模拟温度将升至 95 °C，超过首次运行自动创建的 80 °C 高限规则，可在“报警中心”观察报警触发；取消勾选后，温度恢复并自动恢复报警状态。

这组业务变量是明确标记为 `SIMULATED-BUSINESS` 的演示数据，与模拟 CAN/TCP 原始通信帧分离，不代表任何真实设备协议或硬件测量值。模拟设备断线时，该设备不再生成业务变量。


## 业务变量实时趋势

“实时趋势”页面除原有通信帧率外，新增温度、转速、电流三个独立曲线页签。曲线从统一的 `BusinessDataManager` 读取最新业务数据，按设备筛选并展示最近 60 秒趋势，同时计算当前值、最大值、最小值和平均值。仅质量状态为 Good 且时间戳有效的数据参与曲线统计；无有效数据时会显示提示。模拟数据需先在“实时监控 → 模拟设备”中启动。


## 业务变量历史存储

业务变量在进入 `BusinessDataManager` 最新值缓存的同时，也会异步批量写入 SQLite 的独立 `business_data_history` 表。历史记录保留设备 ID、变量 ID/名称、数值、单位、时间戳、质量状态和来源协议，并建立时间及设备/变量/时间索引。通信原始帧仍保存在 `communication_history`，两类数据互不混用。

`DataManager::queryBusinessDataHistory` 提供按时间范围、设备 ID、变量 ID 查询和分页接口；“历史数据”页面已接入业务变量历史筛选、曲线回放、当前页 CSV 导出，以及按当前时间/设备/变量筛选条件后台流式导出全部记录。


## 业务变量历史页面

“历史数据”页面现分为“通信原始帧”和“业务变量历史”两个页签。业务变量历史支持开始/结束时间、设备编号、变量类型筛选，分页显示时间、设备、变量、数值、单位、质量状态和来源协议；当前页数据可绘制历史曲线并导出带 UTF-8 BOM 的 CSV。支持当前页导出（每页最多 200 条），也支持按当前筛选条件导出全部匹配记录；全量导出在后台线程执行并逐行写入文件，适合大数据量，不会一次性将全部记录读入内存。

### 报警中心规则管理

报警中心提供阈值规则列表，可新增、编辑、删除及启用/禁用规则；报警事件支持按设备 ID、等级和状态筛选，展示活动报警数、今日报警数及平均持续时间，并可将当前筛选结果导出为 UTF-8 CSV。禁用规则会阻止新报警产生，但已有活动事件仍会在后续业务数据恢复到阈值范围时正常关闭。


## 设备管理工程化（本阶段）

- 设备支持分组和独立启用/禁用状态，字段持久化在 SQLite；旧版数据库启动时自动迁移，不要求删除原数据库。
- 设备列表支持多选、分组展示、按设备编号/名称/类型/地址/分组搜索。
- 支持批量启用和批量禁用；禁用设备不会出现在通信配置选择列表中，已连接设备被禁用时会释放通信实例。
- 支持设备配置 JSON 导入/导出；导入时按设备编号匹配，存在则更新，不存在则新增。
- 支持将一台设备的通信类型、设备类型和地址保存为 JSON 通信参数模板，并批量应用到所选设备。模板只复制通信配置，不覆盖设备编号、名称、分组和启用状态。
- 配置导入导出使用版本化 JSON 格式，便于后续扩展字段。

## 历史分页性能优化

- 历史查询不再在每次翻页时同步清空全部待写队列，待写数据由定时批处理继续落库，避免 UI 线程因积压数据而长时间阻塞。
- 时间排序增加复合索引；设备/方向/变量筛选增加分页复合索引。
- 同一组筛选条件翻页时复用总记录数，不重复执行全量 COUNT；用户重新点击查询时才重新统计。
- 通信原始帧和业务变量历史均通过独立 SQLite 连接在线程池中异步查询，查询期间 UI 保持响应，并显示查询状态。
- 表格批量更新期间暂时关闭重绘，完成后统一刷新。
- 查询结果以已提交到 SQLite 的数据为准；尚在写入队列中的最新记录会在后续定时批次提交后出现在查询结果中。


### TCP 自动重连

- TCP 连接发生意外断开或异步连接错误时，通信管理器会自动重试。
- 重试间隔采用 1、2、4、8、16、30 秒指数退避，连接成功后重新计数。
- 手动断开、释放设备或断开全部设备会取消重连，避免用户主动断开后设备又被自动连上。
- 配置页通信日志显示自动重连尝试次数和等待时间。当前只对 TCP 启用；UDP、RS485、CAN/CAN-FD 保持各自链路语义。


## 设备在线状态与心跳监测（本阶段）

- 新增 `DeviceHealthMonitor`，按设备独立记录连接状态、最后一次 RX 时间和在线状态。
- 设备建立连接后先等待首帧；只有实际收到 RX 才标记在线，发送 TX 不会错误地刷新设备存活时间。
- 默认静默超时为 3 秒；“实时监控”页面现有接收超时设置同时控制设备健康监测阈值（1 至 60 秒）。
- 首帧未到、在线后 RX 中断都会产生一次超时事件；收到新 RX 后恢复在线并重新开始计时。
- 手动断开会立即置为离线并清理最后接收时间，不会继续触发超时告警。
- 健康状态变化通过 `DeviceManager` 持久化到设备 SQLite 状态字段，设备管理列表同步显示在线/离线。
- 不定义任何私有心跳报文格式；当前以有效通信 RX 活动作为存活依据。若设备协议以后提供专用心跳帧，可在协议层扩展。


## 通信 I/O 工作线程与资源生命周期

- 每台设备拥有独立的 `CommunicationWorker` 和 I/O 线程；通信驱动对象在所属线程内创建、打开、收发、关闭和销毁。
- TCP/UDP socket、串口和 SLCAN 驱动的事件循环不再依赖 GUI 主线程，降低高频 RX 对界面事件处理的影响。
- `CommunicationManager` 继续作为 UI 侧统一入口；连接和断开在对应设备工作线程执行，发送请求异步入队，避免等待串口/网络写入；数据和状态信号再回到管理器线程。
- TX 历史记录只在驱动成功接受发送数据后生成；配置页显示“TX请求已入队”，避免把排队误报成实际写入成功。
- 每台设备的异步 TX 队列最多积压 1024 条，单次 payload 最大 1 MiB；超过限制会立即拒绝并提示，防止异常发送速率无限占用内存。
- 设备释放时先停止重连、在 I/O 线程关闭并销毁驱动，再退出并等待线程，避免 socket/串口对象跨线程销毁。
- TCP 首次连接异步失败也会进入自动重连流程；自动重连仍按 1、2、4、8、16、30 秒退避。
- 在线状态由 `DeviceHealthMonitor` 独立维护；通信配置页面不再根据 TCP 握手或本地串口打开直接写入在线状态。
- `communication_manager_smoke_test` 增加驱动创建/open/send 线程归属、不同设备线程隔离和首次 TCP 连接失败后的恢复测试。


## 通信诊断中心

通信配置页内置诊断中心：按设备编号和时间范围筛选事件，展示每台设备 TX/RX 次数与字节数、错误和重连次数；最近事件支持 CSV 导出（最多 1000 条）。诊断事件与历史数据共用应用 SQLite 文件，但使用独立数据库连接。TX 计数仅表示驱动成功接受写入，不代表远端已确认收到。


## 历史通信趋势分析

“实时趋势”页面新增历史通信趋势区域，直接读取 SQLite 通信诊断事件并按时间桶聚合，支持全部设备或当前设备筛选，以及最近 1 小时、24 小时、7 天和 30 天范围。曲线分别展示 TX/RX 帧数、错误/超时和重连次数；汇总区同时展示 TX/RX 字节量。时间桶随范围自动调整为 10 秒、1 分钟、5 分钟或 30 分钟，查询限定时间范围并利用诊断时间索引，不将全量事件加载到 UI。支持将当前设备与时间范围的聚合结果导出为 UTF-8 BOM CSV。该图统计诊断事件，不代表远端确认收到的数据或网络 RTT。

## 设备通信质量分析

通信诊断中心按设备展示全量 TX/RX 次数与字节数，并以最近 60 秒事件计算帧率和字节速率；同时显示最近一次 RX 时间、接收静默时长、近 5 分钟错误/超时数量及错误率。质量分级为“良好 / 警告 / 差 / 空闲”，悬停质量状态可查看判定原因。全量累计值通过事务维护的设备汇总表增量更新，历史事件仅按最近 5 分钟时间索引扫描，避免每秒刷新都全表聚合；旧版诊断数据库会自动回填汇总数据，不要求删除数据库。质量指标每秒刷新，不会把 TX 当作设备存活证明；TX 仅代表驱动接受写入，RX 静默时长只描述接收活动，不自行推断设备故障。错误率在样本较少时采用错误数量辅助判定，避免少量事件导致比例失真。


## Modbus 协议帧基础

新增独立 ModbusCodec，与具体通信驱动解耦。当前支持 RTU 与 TCP 请求帧编码、读保持寄存器（0x03）、读输入寄存器（0x04）、写单寄存器（0x06）、写多寄存器（0x10）；RTU 使用 CRC16，TCP 校验 MBAP 协议标识、长度和事务 ID。响应解析覆盖寄存器数据、写入回显和 Modbus 异常码。当前仅完成协议帧层及自动化测试目标，尚未接入 RS485/TCP 轮询界面，也不会假定任何真实设备的寄存器地址或数据缩放规则。
